# Поиск кратчайшего пути. Алгоритм Дейкстры своими руками
Когда мы работаем с графами — например, с дорожными картами, маршрутами поставок, сетями или даже зависимостями между задачами — часто возникает вопрос:  
как найти самый короткий путь между двумя точками?
Самый известный и практичный способ сделать это — **алгоритм Дейкстры**.
Его придумал голландский учёный Эдсгер Дейкстра ещё в 1956 году, но идея до сих пор используется повсюду: от GPS-навигации до логистики и маршрутизации сетей.

## Идея алгоритма

Допустим, у нас есть сеть дорог между городами, и каждая дорога имеет длину (в километрах, минутах, рублях и т.д.).  
Нужно найти **минимальную общую длину пути** от города `A` до всех остальных.

**Интуиция простая:**

1. Мы начинаем с исходной точки (`A`) и считаем, что путь до неё равен 0.
2. Затем смотрим всех её соседей и запоминаем, сколько “стоит” дойти до них.
3. Из всех ещё не посещённых вершин выбираем ту, у которой текущая стоимость минимальна.
4. Повторяем этот процесс, пока не обработаем все вершины.

Постепенно “растёт область” известных кратчайших путей, как будто мы льём воду из источника — она растекается по карте, заполняя вершины от ближних к дальним.

## Пример графа

Пусть у нас есть такой граф (вес — это длина дороги):

```
A -> B (10)
A -> C (3)
B -> C (1)
B -> D (2)
C -> D (8)
C -> E (2)
D -> E (7)
E -> [] (нет исходящих связей)
```

Мы ищем кратчайшие пути **от A ко всем вершинам**.

## Пошаговая логика

1. Инициализируем расстояния:
    - До `A` — 0
    - До остальных — ∞ (пока неизвестно)
2. Отмечаем все вершины как не посещённые.
3. Берём вершину с минимальным расстоянием (сначала это `A`).
4. Для всех её соседей обновляем значения расстояний, если найден более короткий путь.
5. Помечаем вершину как “обработанную”.
6. Повторяем, пока не обработаем все вершины.

### Пример на 1С:Элемент
```
// Алгоритм Дейкстры
// -----------------------------------------------------------
// Назначение: поиск кратчайшего пути от одной вершины ко всем остальным
// Вход: 
//   Граф — структура данных вида <Строка, Массив<Структура {Куда, Вес}>>
//   Начало — имя стартовой вершины (откуда начинаем путь)
// Результат: таблица с кратчайшими расстояниями от "A" до всех вершин

структура ГрафСтруктура
    пер Название: Строка             // имя вершины (например, "A")
    знч Переход: Массив<Соответствие<Строка, Число>> // список соседей и весов
;

// Точка входа: создаём граф и запускаем поиск
метод Скрипт()
    
    // Создаём тестовый граф
    знч Граф = новый Массив<ГрафСтруктура>()

    // Каждая вершина содержит список направлений с весом (стоимость пути)
    Граф.Добавить(новый ГрафСтруктура("A", [{"B":10}, {"C":3}]))
    Граф.Добавить(новый ГрафСтруктура("B", [{"C":1}, {"D":2}]))
    Граф.Добавить(новый ГрафСтруктура("C", [{"D":8}, {"E":2}]))
    Граф.Добавить(новый ГрафСтруктура("D", [{"E":7}]))
    Граф.Добавить(новый ГрафСтруктура("E", [])) // у E нет исходящих рёбер
    
    // Запускаем алгоритм Дейкстры от вершины "A"
    знч Результат = Дейкстра(Граф, "A")

    // Выводим результат на экран
    Консоль.Записать("Кратчайшие расстояния:")
    для Пара из Результат 
        // Если расстояние Неопределено — вершина недостижима
        Консоль.Записать(Пара.Ключ + ": " + (Пара.Значение == Неопределено ? "∞" : Пара.Значение.Представление()))
    ;

;

// Метод Дейкстра — реализует сам алгоритм
метод Дейкстра(Граф: Массив<ГрафСтруктура>, Начало: Строка): Соответствие<Строка, Число?>

    // 1. Таблица расстояний от начальной точки до всех остальных
    //    Формат: { "A": 0, "B": 10, "C": 3, ... }
    знч Расстояния = новый Соответствие<Строка, Число?>()

    // Массив для хранения уже посещённых вершин
    знч Посещенные = новый Массив<Строка>()

    // 1. Инициализация расстояний
    для Узел из Граф
        если Узел.Название == Начало 
            // Для стартовой вершины расстояние = 0
            Расстояния[Узел.Название] = 0
        иначе
            // Остальные пока недостижимы
            Расстояния[Узел.Название] = Неопределено
        ;
    ;

    // 2. Основной цикл
    // Пока не обработаны все вершины — ищем минимальные пути
    пока Посещенные.Размер() < Граф.Размер()

        // 2.1 Найдём непосещённую вершину с минимальным расстоянием
        // Это текущая "точка роста" — ближайшая из ещё не обработанных
        пер Текущая = ""                  // имя текущей вершины
        пер МинДистанция: Число?          // минимальное расстояние
        пер ТекущийУзел: ГрафСтруктура?   // ссылка на сам объект вершины

        // Проходим все расстояния
        для Пара из Расстояния 
            если не Посещенные.Содержит(Пара.Ключ) 
                если Пара.Значение != Неопределено 
                    // Если нашли вершину с меньшей дистанцией — обновляем минимум
                    если МинДистанция == Неопределено или (Пара.Значение ?? 0) < МинДистанция 
                        МинДистанция = Пара.Значение
                        Текущая = Пара.Ключ
                    ;
                ;
            ;
        ;

        // Если не найдено непосещённых вершин — завершаем
        если Текущая == "" 
            прервать
        ;
        
        // 2.2 Находим сам объект текущей вершины в графе
        для Узел из Граф 
            если Узел.Название == Текущая 
                ТекущийУзел = Узел
                прервать
            ;
        ;

        // 2.3 Обновляем расстояния до соседей
        // Для всех рёбер, исходящих из текущей вершины:
        //   если путь через неё короче — обновляем значение
        для Переход из ТекущийУзел.Переход
            для Направление из Переход
                пер Куда = Направление.Ключ   // имя соседней вершины
                пер Вес = Направление.Значение // "стоимость" перехода

                // Текущее расстояние до выбранной вершины
                пер ТекущееРасстояние = Расстояния[Текущая]

                // Возможное новое расстояние через текущую вершину
                пер НовоеРасстояние = ТекущееРасстояние + Вес

                // Если новый путь короче — обновляем значение
                если Расстояния[Куда] == Неопределено или НовоеРасстояние < Расстояния[Куда]
                    Расстояния[Куда] = НовоеРасстояние
                ;
            ;
        ;

        // 2.4 Помечаем текущую вершину как посещённую
        Посещенные.Добавить(Текущая)
    ;

    // Возвращаем таблицу кратчайших расстояний
    возврат Расстояния
;
```

Результат

```
Кратчайшие расстояния:
A: 0
B: 10
C: 3
D: 11
E: 5
```
Это означает, что кратчайший путь из `A` в `E` проходит через `C`:  **A → C → E (5)**.
### Заключение

Алгоритм Дейкстры — это простой, интуитивно понятный и чрезвычайно практичный инструмент для поиска кратчайших путей в взвешенных графах с неотрицательными весами. Его сила в последовательном «расползании» минимальных расстояний от стартовой вершины: на каждом шаге алгоритм расширяет область уже доказанных оптимальных путей, гарантированно находя кратчайшие расстояния до всех достижимых вершин.

На практике Дейкстра отлично подходит для задач маршрутизации, планирования логистики, анализа сетей и многих других приложений, где веса рёбер неотрицательны. Важные моменты, которые нужно помнить при использовании алгоритма:

- базовая реализация без структуры приоритетов проста и наглядна, но работает за O(V²) — приемлемо для небольших графов;
    
- для больших графов стоит использовать приоритетную очередь (кучу) — тогда сложность уменьшается до O((V + E) log V);
    
- алгоритм не годится для графов с отрицательными весами — в таких случаях требуются другие методы (например, алгоритм Беллмана–Форда).
    

Если нужна не только длина, но и сам маршрут — достаточно сохранять предков (parent) при обновлении расстояний, а по окончании восстанавливать путь от целевой вершины до стартовой. Для задач поиска между двумя конкретными вершинами стоит рассмотреть A* — он добавляет эвристику и может существенно сократить количество обрабатываемых вершин.

В итоге: реализовав Дейкстру «своими руками», вы не только получаете рабочее решение для множества практических задач, но и лучше понимаете фундаментальную идею жадных алгоритмов и работу с графовыми структурами. Это отличный базовый инструмент — и платформа для дальнейших оптимизаций и улучшений в зависимости от требований задачи.
